# Bun Burner v0.1.0-beta.1

Bun Burner is a small Bun/TypeScript bridge for opt-in, two-way source synchronization between a local scripts folder and Bitburner's Remote API.

- Preserves original `.js`, `.jsx`, `.ts` and `.tsx` source, filenames and line endings. No required compilation, transpilation or bundling.
- Manually validated with Steam Bitburner 3.0.1 on Fedora 44 KDE and Windows x64, using Bun 1.4.2. Relative and normal absolute local roots, transfers, conflicts/recovery, restart/reconnect, lock release and filesystem diagnostics have been exercised.
- Uses content baselines, serialized transfers, pre-write rechecks, destination verification and recovery copies. Ambiguous conflicts are preserved rather than silently resolved.
- Does not propagate deletions. A tracked file missing on one side is a conflict; a missing configured root pauses sync without creating a replacement workspace or inferring game-side deletion.
- Includes safe, idempotent `bun run init`, `bun run verify` and optional `bun run verify:push`. Linux and Windows CI runs automated tests and typechecks; simulated WebSocket tests are distinct from live Steam validation.

## Known limitations

This is beta software. Begin with disposable or backed-up scripts and retain your own backups. Source preservation and conservative sync decisions are not guarantees against every operating-system, editor or concurrent-write failure.

- **OneDrive and other cloud-backed folders: unvalidated, non-blocking, community testing welcome.** Disposable probes observed transient busy-file errors without establishing their owner; healthy live cloud synchronization has not been qualified. Prefer an ordinary local root unless intentionally testing with backed-up or disposable scripts.
- macOS and browser Bitburner remain unvalidated; this beta targets Steam desktop on Linux and Windows. Other Linux distributions have not been personally validated.
- An open Bitburner editor tab can retain older source after an external update. Preserve any unsaved edits, use the tab's circular-arrows control to reload the server contents, confirm, and inspect before saving. The tested refresh-then-save sequence preserved the current source; saving a stale buffer restored its old contents. This is documented workflow behavior, not a confirmed bug in either application.
- The Remote API has no atomic conditional writes, so simultaneous editing is not race-free. Polling is intended for modest script workspaces. TLS/WSS and deletion propagation are not implemented.
- Normal shutdown releases the workspace lock. After abnormal termination, inspect the recorded process before removing a stale lock. Other editors may keep workspace handles open after Bun Burner exits.

## Getting started and feedback

Install Bun 1.4.2 and Git, then follow the [README quick start](../../README.md#-quick-start): clone, `bun install --frozen-lockfile`, `bun run init`, review `.env`, opt into sync, and `bun run start`. Connect Bitburner's Remote API to `ws://127.0.0.1:12525` unless you changed the listener settings.

[Compatibility reports and reproducible bug reports](https://github.com/NathanMartinez/bun-burner/issues) are welcome. Include OS, Bun/Bitburner versions, root type, editor, exact steps and expected/observed behavior. Use disposable reproductions and omit private source or credentials.
